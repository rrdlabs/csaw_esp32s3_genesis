board and the verification performed before delivery. It is the release
manifest for the merged artifact; the firmware source and build recipe remain

## 3. Flash

The board's USB-UART bridge must be enumerated (typically `/dev/ttyUSB0`) and
the ESP32-S3 in download mode. The merged image contains every region, so a
single write at offset `0x0` is sufficient.

```bash
# One-line esptool flash of the merged image
python -m esptool --chip esp32s3 -b 460800 --before default-reset \
  --after hard-reset --flash-mode dio --flash-size 16MB --flash-freq 80m \
  write-flash 0x0 build/merged-binary.bin
```

Equivalent per-region command (generated by IDF, `build/flash_args`):

```
0x0      build/bootloader/bootloader.bin
0x8000   build/partition_table/partition-table.bin
0xf000   build/ota_data_initial.bin
0x20000  build/csaw.bin
0x420000 build/spiffs.bin
```

`scripts/flash_genesis_merged.sh` wraps the one-line command with a port
argument. `idf.py -p /dev/ttyUSB0 flash monitor` is the developer alternative.

## 5. Verification performed (offline, all PASS)

| App/partition sizing | `check_sizes.py --offset 0x8000 partition --type app …` | app `0x1ecad0` < `0x200000`; 4 % free |

## 6. Hardware verification — NOT PERFORMED (no device attached)

This container has **no physical Genesis board**. The build image is verified
structurally as above, but no flash/boot/hardware bringup check was possible.
Attempted commands and their exact results:

```
$ ls -l /dev/ttyUSB* /dev/ttyACM* /dev/serial/by-id
  -> no such files (only /dev/tty* virtual consoles present)

$ lsusb
  Bus 001 Device 001: ID 1d6b:0002 Linux Foundation 2.0 root hub
  Bus 002 Device 001: ID 1d6b:0003 Linux Foundation 3.0 root hub
  -> no USB-UART bridge or Espressif device enumerated

$ python -m esptool --chip esp32s3 --port /dev/ttyUSB0 chip-id
$ python -m esptool --chip esp32s3 --port /dev/ttyUSB1 chip-id
$ python -m esptool --chip esp32s3 --port /dev/ttyACM0 chip-id
$ python -m esptool --chip esp32s3 --port /dev/ttyACM1 chip-id
  -> "Hint: Check if the port is correct and ESP connected"

$ python -m esptool --chip esp32s3 chip-id
  ERROR: /dev/ttyS0 failed to connect: Could not open /dev/ttyS0, the port is busy or doesn't exist.
  ERROR: A fatal error occurred: Could not connect to an Espressif device on any of the 8 available serial ports.
```

**Consequence:** the secondary BSP repository described in the operator
request is gated on "hardware passes". That gate cannot be satisfied in this
environment. No BSP repo has been created. See
[IMPLEMENTATION_PROGRESS.md](IMPLEMENTATION_PROGRESS.md) for the operator
decision and the prepared BSP content manifest.
